# Native regression runner

Run `python3 tools/test_native_roots.py --idf-path "$IDF_PATH" --output "$PWD/native-results"` with a new output directory. Requirements are Python 3, CMake, a C compiler with pthreads, and the Python dependencies needed by ESP-IDF's certificate generator (`cryptography`). Use an unmodified ESP-IDF v6.0.2 checkout with its `components/mbedtls/mbedtls` submodule initialized. The runner checks SDK commit `7101770dc6db2667b3c477cc31365dd1acd6db4e` and mbedTLS commit `6cc42afad309e861f4c07e6f106e2ab14a9cb8e5`, compiles their native libraries and the production helper, and never opens sockets, serial ports, or devices. SDK sources remain read-only.

Frozen public peer chains reproduce three full-chain compact-bundle failures, shortened-chain controls, and unaffected endpoints. At test time the runner reads all 12 incident fixtures from the existing checksum-pinned incident archive and generates the native root representation from the existing pinned PEM into its isolated output directory. `self.pem` and `attacker-full.pem` are synthetic certificate-only negatives, without private keys. The latter has a same-subject, different-key root impersonating GTS Root R4. `bad-signature.pem` flips the last signature byte of the Discord leaf while preserving the rest of its chain. `sha256.json` binds every fixture. Frozen-fixture validity is not live endpoint acceptance: the native test build follows the application's inherited disabled time/date policy, without changing production policy.

The suite checks native wrong-host, self-signed, impostor, signature, and incident denials; attach replacement of a stale verification hook; all 118 approved roots, equivalent parsed names through the SDK's exact comparator bodies, parser/selection allocation cleanup, complete positive and negative allocation sweeps, concurrent verifier lifecycles, malformed registries, and candidate/byte bounds. Name equivalence tests modify parsed name fields while retaining signed DER and are not forged signed fixtures. Process-global PSA RNG and key-slot initialization occurs before fixed allocator hooks and per-client accounting. Good chains may survive optional native allocation failures; success must have zero flags, no lookup error, and zero residual client allocations. The fault sweep is not an exhaustive exploration of all allocation-dependent paths.

`commands.log` and `results.json` are local evidence, not committed outputs. Historical private host transport and target-build qualification is separate. CI runs this offline suite on Linux; local Darwin execution is not a claim that Linux CI has already passed. This is not target heap/PSRAM, task-stack, concurrent transport, or real pool qualification, and does not authorize installation.
